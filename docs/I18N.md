# Turtle Flight — Localization (i18n) Guide

**Status as of v1.0:** ko (primary) + en (development region) shipping.
**Backlog (CLAUDE.md follow-up):** ja, zh-Hans, es, fr, de — RN had these
in flight before the rollback; v1.x will reintroduce them via the native
pipeline below.

## File layout

```
TurtleFlight/Resources/
├── ko.lproj/
│   └── Localizable.strings
└── en.lproj/
    └── Localizable.strings
```

To add a new locale, create `<locale>.lproj/Localizable.strings` next to
the existing two and add the locale code to `Info.plist`'s
`CFBundleLocalizations` array.

## Key conventions

- **Hierarchical, dot-separated:** `<screen>.<element>(.<subkey>)`
- **One key per logical message;** reuse via `common.*` only when the
  phrasing genuinely matches across contexts.
- **Format placeholders use `%lld` for `Int`/`Int64`, `%@` for `String`**
  to play nice with `String(format:)`.
- **Never inline strings into Swift source.** All player-visible text
  must go through `L10n.t(_:)` or `L10n.format(_:_:)` from
  `TurtleFlight/Utils/L10n.swift`.

## Verification

`Tests/LocalizationCoverageTests.swift` enforces that:

1. Every theme has `theme.<id>.displayName` / `subtitle` / `region.0…7`.
2. Every stage has `stage.<n>.name` / `description` / `star3Condition`.
3. `MapTheme.displayName` resolves through the bundle (not a hard-coded
   English literal in code).

Add a new test case there for any new key family.

## Adding a new locale

1. **Translate.** Copy `en.lproj/Localizable.strings` to
   `<locale>.lproj/Localizable.strings`. Translate values; keep keys
   identical.
2. **Register.** Add `<locale>` to `CFBundleLocalizations` in
   `TurtleFlight/Info.plist`.
3. **QA.** Run the app in the new locale (Scheme → Run → Options →
   Application Language). Spot-check:
   - Home title + subtitle.
   - Mode picker (Free Flight / Step Goal).
   - Sensitivity tier names.
   - StageSelectView descriptions + star conditions.
   - HUD region label cycles through localized region names.
   - SettingsView (Mute / volumes / Reset / Privacy / Support / Credits).
   - Onboarding three-card sequence.
4. **Run `LocalizationCoverageTests`.** All 8 cases must pass for the
   new bundle.
5. **Marketing copy.** App Store metadata (description, keywords,
   screenshots) is shipped via App Store Connect, **not** the bundle.
   Hand off to the marketing translation pipeline separately.

## Style notes per locale

- **ja** — informal style, short sentences, no English brand words
  inside body copy. Stage names can keep their kanji-katakana mixed
  form (e.g., 「空の散歩」).
- **zh-Hans** — simplified characters; 2-3-character stage names where
  possible to fit the StageSelectView card.
- **es / fr / de** — informal "you" form (tú / tu / du). Watch for
  layout overflow on `mission.fail.timeout` (German is 1.4× the English
  string length on average).

## What NOT to translate

- `flight.gyro.unavailable.continue` — already says "Continue" in
  English; the standard English fallback is fine even on partial
  translations.
- Asset names (e.g., `turbo_default`) — they're identifiers, not text.
- `personality` field — **deleted in Sprint 1.** Don't reintroduce as a
  hard-coded string in source.
